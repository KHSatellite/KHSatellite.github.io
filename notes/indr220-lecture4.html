INDR 220 Lecture 4

Warehouse Location Problem

Bu derste gerçekçi, tam bir modelleme örneği yapıyoruz: depo yeri seçimi. Önce Σ'lı modeli kuruyor, sonra onu adım adım A·x (=, <=) b matrislerine çeviriyoruz. Lecture 02'deki binary değişkenlerle Lecture 03'teki matris dilini birleştiriyoruz.

1. Problem

Bir şirket müşterilerine ürün gönderiyor. Şehirde birkaç aday depo konumu var (şekilde W1, W2, W3) ve müşteriler (C1..C6) farklı yerlerde. Soru: Hangi depoları açmalıyım ve her müşteriye hangi depodan ne kadar ürün göndermeliyim ki toplam maliyet minimum olsun?

İki tür maliyet var ve birbiriyle çelişiyor: - Depo açmak pahalı (kira, işletme) → az depo açmak isterim. - Müşteriye uzak depodan göndermek pahalı (taşıma) → çok depo açıp müşteriye yaklaşmak isterim.

Optimization bu dengeyi bizim yerimize kurar.

Notasyon (parametreler, yani input)

Sembol Anlam
N aday depo sayısı
M müşteri sayısı
dj müşteri j'nin talebi (demand)
fi depo i'nin sabit / işletme maliyeti (açılırsa ödenir)
cij j. müşteriye i. depodan bir birim göndermenin maliyeti (genelde depo–müşteri mesafesiyle orantılı: cij ∝ distance)

Karar değişkenleri (output)

Burada iki farklı türde karar var, bu yüzden iki değişken ailesi:

yi = 1 eğer depo i açılırsa (binary, evet/hayır) 0 aksi halde xij = depo i'den müşteri j'ye gönderilen ürün miktarı (continuous, ≥ 0)
Dikkat: yi binary, xij sürekli. Yani bu problem bir MILP'tir (Lecture 02'deki "mixed" sınıf).

2. Modeli kuralım

Objective

minimize Σ(i=1..N) fi · yi + Σ(i=1..N) Σ(j=1..M) cij · xij └ total investment ┘ └──── total transportation cost ────┘ (toplam yatırım maliyeti) (toplam taşıma maliyeti)
  • İlk toplam: yalnızca açılan depoların (yi = 1) sabit maliyeti ödenir; kapalı depo (yi = 0) için fi·0 = 0.
  • İkinci toplam: gönderilen miktar × birim maliyet.

Constraint 1 — Her müşterinin talebi tam karşılanmalı

Σ(i=1..N) xij = dj j = 1, 2, ..., M (her müşteri için)

Müşteri j'ye tüm depolardan gelen miktarların toplamı = onun talebi. (M tane constraint.)

Constraint 2 — Kapalı depo ürün gönderemez

Bunu ifade etmek zor ve zeki bir numara. Şöyle yazılıyor:

Σ(j=1..M) xij − ( Σ(j=1..M) dj ) · yi <= 0 i = 1, 2, ..., N (her depo için)

Anlamı: TD = Σ dj (total demand, toplam talep) diyelim. Bu constraint'i Σ xij <= TD · yi diye de okuyabilirsiniz. İki durum:

  • yi = 0 (depo kapalı): Σ xij <= 0. Ve xij ≥ 0 olduğundan → hepsi 0. Kapalı depo hiçbir şey gönderemez. ✔
  • yi = 1 (depo açık): Σ xij <= TD. Depo, toplam talebe kadar gönderebilir; pratikte hiçbir kısıt yok. ✔

Yani yi, "bu depo çalışıyor mu?" şalteri gibi bir kapı görevi görüyor. (Bu hileye ileride birçok problemde rastlayacağız: binary değişkenle sürekli değişkeni bağlamak.) Sağdaki sabit (TD) "yeterince büyük" olmalı; burada toplam talep zaten doğal bir üst sınır.

Bound'lar / değişken tipleri

yi ∈ {0, 1} i = 1, ..., N xij >= 0 i = 1, ..., N ; j = 1, ..., M

Sayılarla boyut kontrolü

# decision variables = N + N·M (N tane yi + N·M tane xij) # constraints = M + N (M talep constraint'i + N kapasite constraint'i)

3. Matris formuna çevirelim (N = 2, M = 3)

Genel N, M ile yazmak göz karıştırır. Küçük örnekle bakalım: 2 depo, 3 müşteri. Değişken sayısı: 2 + 2·3 = 8. Constraint sayısı: 3 + 2 = 5.

Adım 1: Karar değişkenlerini tek bir vektöre diz

Solver tek bir x vektörü ister. Bu yüzden xij'leri (matris gibi düşünebileceğimiz 2×3 yapıyı) ve y'leri alt alta dizeriz. Sıra:

x = [ x11 x12 x13 x21 x22 x23 y1 y2 ]^T boyut: (NM + N) x 1 = 8 x 1 └─ depo 1 ──┘ └─ depo 2 ──┘ └ y'ler ┘

(Önce 1. deponun müşterilere gönderdikleri, sonra 2. depo, en sonda y'ler.)

Adım 2: Objective → c

Katsayıları da aynı sırayla dizeriz:

c^T = [ c11 c12 c13 c21 c22 c23 f1 f2 ] boyut: 1 x 8 minimize c^T · x = c11·x11 + c12·x12 + ... + c23·x23 + f1·y1 + f2·y2
Kural: x'in sırası neyse, c, A'nın sütunları ve l, u aynı sırayı izlemeli. Sıra karışırsa model yanlış olur.

Adım 3: Talep constraint'leri → A1 · x = b1

Yazılışı:

x11 + x21 = d1 (1. müşteri) x12 + x22 = d2 (2. müşteri) x13 + x23 = d3 (3. müşteri)

Her satırı 8 değişkenin hepsi için yazalım (olmayanların katsayısı 0):

1·x11 + 0·x12 + 0·x13 + 1·x21 + 0·x22 + 0·x23 + 0·y1 + 0·y2 = d1 0·x11 + 1·x12 + 0·x13 + 0·x21 + 1·x22 + 0·x23 + 0·y1 + 0·y2 = d2 0·x11 + 0·x12 + 1·x13 + 0·x21 + 0·x22 + 1·x23 + 0·y1 + 0·y2 = d3

Katsayıları matrise yazarsak:

x11 x12 x13 | x21 x22 x23 | y1 y2 [ 1 0 0 | 1 0 0 | 0 0 ] [d1] A1 = [ 0 1 0 | 0 1 0 | 0 0 ] b1 = [d2] [ 0 0 1 | 0 0 1 | 0 0 ] [d3] └─ I (MxM) ─┘ └─ I (MxM) ─┘ └ 0 (MxN)┘

Güzel bir yapı: iki tane birim matris (identity, M×M) yan yana, sonra sıfırlar. Boyut: A1: M × (NM + N), b1: M × 1.

Neden birim matris? Çünkü her depo bloğunda "j. müşteri → j. satır" eşleşmesi var.

Adım 4: Depo constraint'leri → A2 · x <= b2

x11 + x12 + x13 − TD·y1 <= 0 (1. depo) x21 + x22 + x23 − TD·y2 <= 0 (2. depo)

Matris:

x11 x12 x13 | x21 x22 x23 | y1 y2 [ 1 1 1 | 0 0 0 | -TD 0 ] [0] A2 = [ 0 0 0 | 1 1 1 | 0 -TD ] b2 = [0] └─ N x M ──┘ └─ N x M ──┘ └── N x N ─┘

Boyut: A2: N × (NM + N), b2: N × 1.

Adım 5: A1 ve A2'yi tek matriste topla

İki ayrı constraint grubumuz var, biri eşitlik, biri eşitsizlik:

A1 · x = b1 (eşitlik) A2 · x <= b2 (eşitsizlik)

Alt alta dizilmiş hali:

[ A1 ] [ = ] [ b1 ] [ A2 ] · x [ <= ] [ b2 ]

Yani artık solver'a: c, A1, b1, A2, b2 ve bound'ları (yi ∈ [0,1] ve integer, xij ≥ 0) vereceğiz.

Not: Lecture 03'te LP'yi sadece A x <= b ile yazmıştık. Gerçek problemlerde eşitlikler de çok çıkar, bu yüzden pratikte solver'lar iki matris ister (eşitlik için ayrı, eşitsizlik için ayrı). Bu fikir buradaki A1 x = b1 ve A2 x <= b2 ayrımıdır. (Ek not, derste yazılmadı: bir eşitlik, iki eşitsizlikle — <= ve >= — de ifade edilebilir; bu yüzden teorik olarak sadece <= yeterlidir.)

4. Bu dersin en önemli dersi: Modelleme → Matris çeviri tarifi

Bir problemi bilgisayara vermek için sırayla:

  1. Değişkenleri tanımla (hangi indisler, hangi tipler: binary / continuous).
  2. Tek vektörde sırala (x = [...]). Sırayı bir kere seç, sonra değiştirme.
  3. c vektörünü aynı sırayla doldur.
  4. Her constraint ailesi için ayrı bir blok matris (A1, A2, ...) ve sağ taraf vektörü (b1, b2, ...) yaz. Olmayan değişkenlere 0 koy.
  5. Blokları alt alta dizerek A ve b'yi elde et.
  6. l ve u'yu (bound'lar) doldur. Binary değişken ise [0,1] bound + integer işareti.

Bu işi elle yapmak sıkıcı (ve hata yapmaya açık). Bu yüzden önümüzdeki derslerde NumPy gibi kütüphanelerle matris kurmayı öğreniyoruz. (Lecture 05'te başlıyoruz.)

Özet

  • Warehouse Location: hangi depolar açılsın (binary yi) ve kim kimden ne kadar alsın (sürekli xij)?
  • Objective = sabit maliyetler + taşıma maliyetleri.
  • Talep constraint'i: her müşteri için Σi xij = dj.
  • "Kapalı depo gönderemez" constraint'i: Σj xij − (Σj dj)·yi <= 0 (binary ile sürekliyi bağlama hilesi).
  • Değişken sayısı N + NM, constraint sayısı M + N.
  • Matrise çevirmek: tüm değişkenleri tek vektöre diz, c / A1 / A2 / b1 / b2'yi aynı sırayla kur.
  • Bu bir MILP'tir.

Kendini test et

  1. N = 3 depo, M = 5 müşteri için kaç değişken ve kaç constraint var?
  2. Constraint 2'de yi = 1 iken kısıt "bir şey kısıtlamıyor" gibi duruyor. Peki depoya bir kapasite (örn. en fazla Ki birim) koymak istesek ne yazardık?
  3. x vektöründe sıralamayı değiştirip y'leri başa alsak neler değişir?
Cevapları Gör
  1. Değişken: N + NM = 3 + 15 = 18. Constraint: M + N = 5 + 3 = 8.
  2. Σj xij <= Ki · yi yazardık. (TD yerine kapasite Ki gelir.) yi = 0 ise yine 0 gönderir, yi = 1 ise en fazla Ki gönderir. (Mantık sorusu; derste işlenmedi.)
  3. Modelin kendisi değişmez; ama c, A1, A2 ve l, u'nun sütun sırası da aynı şekilde değişmek zorundadır. Hepsi aynı sıralamayı izlemezse model bozulur.
